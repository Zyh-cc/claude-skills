# 中文学术论文 AI 腔检查与修改流程

## 版本日志

## 问题场景

用 Claude 起草中文学术论文（绪论、综述）后，需要在提交导师审阅前做 AI 腔检查，降低 AI 写作检测风险，使文字读起来更接近人类学者的论述风格。

---

## 七类 AI 腔模式与修改方法

### 模式1：排比枚举（最典型）

**识别**：`其一…其二…其三`、`首先…其次…再次…最后`、`第一…第二…第三`

**问题**：AI 偏好对称结构，人类学者更多使用因果关系或递进论证。

**修改**：
- 三条以上枚举 → 拆分为多段，每段自然展开一个论点
- 两个对比项 → 用"在X上…在Y上…"或"X的局限在于…这一特征决定了…"
- 保留序号的场合（如表格的"研究空白/本文创新"）可例外

**例**
```
改前：
其一，仿真类数据集的遮挡标注依赖引擎底层接口，真实采集环境中无法复现；
其二，真实场景数据集的地面端均为移动车辆，缺乏固定路侧基础设施视角；
其三，所有现有数据集均未提供真实场景下的遮挡感知标注。

改后（两段分类型论述）：
仿真类数据集虽能提供系统性的遮挡可见度标注，但 Griffin 的实现方式与引擎底层接口深度耦合，无法迁移至真实采集流程，域差距问题亦无从回避。真实场景数据集消除了物理保真度的疑虑，但 AGC-Drive 与 V2U4Real 均以移动车辆作为地面端，遮挡感知标注在两个数据集中均未提供。
```

---

### 模式2：定义句开段

**识别**：段落第一句是对某概念/方法的定义，如"X是指…"、"X方法通过…实现了…"

**问题**：教科书写法，AI 喜欢"先下定义再举例"；学术论文更常见"先给出发现/问题/数据"。

**修改**：段落改为以**具体发现、失败案例、关键数字**开头。

**例**
```
改前：
高质量标注数据集的有效性依赖系统化的质量评估机制。在标注一致性评估方面，
标注内一致性（IAA）是量化多标注员之间标注差异的核心指标…

改后：
标注质量的评估不能只靠主观审核。多标注员之间的标注一致性（IAA）通过
Cohen's Kappa 系数量化，Kappa 值排除随机一致的干扰，κ > 0.8 通常作为
高质量标注的验收阈值。
```

---

### 模式3："方面"/"上述"过度使用

**识别**：全文 grep `方面` 和 `上述`，出现频次

**阈值**：
- `方面`：≤3 次，且每次均为不可替换的用法
- `上述`：≤2 次，仅用于真正需要向上指代的场合

**修改**：
- "在X方面" → 直接陈述 X（"路侧激光雷达的安装高度…"而非"在安装高度方面…"）
- "上述研究" → 指代具体（"Griffin 与 AGC-Drive"）或用"这些工作"
- "上述三项局限" → 用"两类缺口"或直接将内容内嵌

---

### 模式4：句长均质化

**识别**：阅读时节奏感均匀，几乎每句都是25-35字的长句

**问题**：AI 倾向于生成近似等长的句子。

**修改**：主动混入短句（8-15字）打断节奏，尤其在段落末尾和转折处。

**例**
```
改前（全为长句）：
…AGC-Drive正是在这一问题上遭遇了困境，其采用GPS辅以ICP进行配准，配准后
依然存在几何残差，根因在于俯仰角畸变未在配准前得到校正。

改后（末尾加短句）：
AGC-Drive正是在这一问题上遭遇了困境——其采用GPS辅以ICP进行配准，配准后
依然存在几何残差，根因在于俯仰角畸变未在配准前得到校正。根因很清楚，但
在现有真实数据集中从未被系统解决。
```

---

### 模式5：AI 过渡句

**识别**：以下句式直接砍掉或改写：
- "上述研究共同表明…"
- "由此可见…"
- "综上所述…"
- "这些工作为…奠定了基础"
- "这一趋势说明…"

**修改**：过渡信息直接内嵌到下一段的开头作为起因（而非在上一段末尾重复）。

---

### 模式6：括号滥用

**规则（严格执行）**：
- ✅ 允许：引用编号 `[1]`、缩写首次定义 `激光雷达（LiDAR）`
- ❌ 禁止：术语解释 `（即路侧感知单元）`、限定说明 `（尤其是路口场景）`

**修改**：括号内说明改为前置定语或另起短句。

---

### 模式7：空洞强调词

**黑名单**（出现即删）：
`至关重要`、`里程碑式`、`开创性地`、`显著提升了`（无数据）、`具有重要意义`、`不可或缺`

---

## 检查流程（逐步执行）

```
Step 1：全文 grep 排比触发词（其一/首先其次/第一第二）→ 逐一重构
Step 2：全文 grep "方面" → 超过3处，压缩最薄弱的用法
Step 3：全文 grep "上述" → 超过2处，替换为具体指代
Step 4：逐段检查第一句 → 若为定义句，改为事实/发现/案例开头
Step 5：通读，感受句子节奏 → 节奏过均匀则在段末或转折处插入短句
Step 6：全文 grep 黑名单词汇 → 删除或替换为有数据支撑的描述
Step 7：检查所有括号 → 非引用、非首次缩写的括号全部改写
```

## 质量验收标准

- 每段开头：至少50%的段落不以定义句开头
- `方面` ≤ 3次（全文）
- `上述` ≤ 2次（全文）
- 无排比枚举结构（其一/其二/其三类）
- 无黑名单词汇
- 段落内句子长度最大/最小比例 > 2（即有明显节奏变化）

## 踩过的坑

| 坑 | 原因 | 解决 |
|----|------|------|
| 改掉排比后逻辑变散 | 原文的逻辑依赖列表结构维持，改后连接词缺失 | 拆分为"按问题类型"的两段，每段有独立论据 |
| 把必要的"方面"也删掉 | grep 后机械删除 | 先问"能用更精确的动词或名词替代吗"，不能替代则保留 |
| 改了句长但读起来碎 | 短句插入位置随机 | 短句只在段末总结或论点转折时插入，不在论证中途打断 |
