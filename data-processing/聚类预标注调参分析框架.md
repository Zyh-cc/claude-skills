# 点云聚类预标注调参分析框架（置信度分层 + 漏检/误报诊断）

## 版本日志
| 版本 | 日期 | 变更内容 |
|------|------|----------|
| v1.0 | 2026-04-13 | 初始版本，来自 AeroGround-Dataset 预标注工具链 |

## 问题场景

对点云（DBSCAN/HDBSCAN）聚类结果做规则过滤后，需要评估参数设置是否合理：
- 哪些被接受的目标质量较低（潜在误报）？
- 哪些被拒绝的目标可能是漏检（仅微超某一阈值）？
- 哪些参数对目标质量区分度最高（指导调参方向）？

适用于任何"聚类 → 规则过滤 → KITTI 输出"的预标注场景。

---

## 解决方案

### 核心设计：置信度评分 + 四节诊断

#### 1. 置信度评分系统

**舒适度函数**：度量一个值在参数范围 [lo, hi] 内的居中程度（0=在边界上，1=正中央）：

```python
def _comfort(v: float, lo: float, hi: float) -> float:
    half = (hi - lo) / 2
    if half <= 0:
        return 1.0
    return max(0.0, 1.0 - abs(v - (lo + hi) / 2) / half)
```

**子分项设计**（针对车辆 bbox，可按场景调整）：

| 子分项 | 计算方式 | 含义 |
|--------|---------|------|
| `size_score` | l/w/h 三项舒适度均值 | 尺寸是否居中于参数范围 |
| `shape_score` | 长宽比舒适度 + Z标准差余量 均值 | 形状是否规整 |
| `density_score` | `min(n_pts / REF_PTS, 1.0)` | 点数是否充足（REF_PTS=150） |

**加权合并**（权重可调）：
```python
confidence = round((3 * size_score + 3 * shape_score + 2 * density_score) / 8, 3)
```

**分层阈值**（针对车辆可视化）：
- HIGH ≥ 0.70（绿色）
- MED 0.45~0.70（蓝色）
- LOW < 0.45（红色，优先人工审核）

#### 2. 四节诊断框架（`analyze_detail.py` 模式）

**【1】分层统计**：HIGH/MED/LOW 三列表格，对核心字段（n_pts/l/w/h/aspect/z_std）输出 均值±std。
额外输出参数敏感度：HIGH均值 vs LOW均值 相对差异排名，差异>30%标注为「重点」——这是调参时应优先关注的字段。

**【2】疑似漏检**（near-miss）：在被拒绝的簇中，找出"几乎通过"的候选。
判定条件：失败项数 ≤ `miss_max_fail`，且所有失败项超出幅度 ≤ `miss_overshoot`。
```python
denom = hi if v > hi else lo
overshoot = max(lo - v, v - hi, 0) / denom if denom else 0
```
对每个候选附上与 HIGH 均值的偏差描述（如 `l↑18%  h↓5%`），方便人工判断是否放宽阈值。

**【3】LOW 置信度优先审核**：
列出置信度 <0.45 的接受目标，并按弱项从低到高排列子分（`density=0.14  shape=0.21  size=0.62`），帮助快速定位改进方向。

**【4】疑似误报**（仅 MED/HIGH 中检测）：
- **边界偏近**：某字段值距最近阈值边界 < `boundary_tol × 参数范围`（默认12%）
- **统计离群**：`|z-score| > zscore_thresh`（默认2.0σ），相对全量接受目标的均值和标准差
按置信度升序排列（置信度越低越可疑，排前面）。

#### 3. 可调阈值

| 参数 | 默认 | 说明 |
|------|------|------|
| `miss_max_fail` | 2 | 疑似漏检：允许失败的指标项数上限 |
| `miss_overshoot` | 0.20 | 疑似漏检：失败项超出幅度上限（20%） |
| `boundary_tol` | 0.12 | 疑似误报：贴近边界的相对距离阈值 |
| `zscore_thresh` | 2.0 | 疑似误报：统计离群 z-score 阈值 |

预设档位（快速切换，GUI滑块）：

| 档位 | miss_max_fail | miss_overshoot | boundary_tol | zscore_thresh |
|------|--------------|----------------|-------------|--------------|
| 默认 | 2 | 20% | 12% | 2.0 |
| 严格 | 1 | 10% | 8% | 1.5 |
| 宽松 | 3 | 30% | 18% | 2.5 |
| 极宽 | 3 | 50% | 25% | 3.0 |

## 实现关键点

### detail JSON 结构
```json
{
  "params": { "cluster_algo": "DBSCAN", "eps": 0.8, ... },
  "accepted": [
    { "n_pts": 47, "l": 4.821, "w": 1.934, "h": 1.203,
      "aspect": 2.494, "z_std": 0.312,
      "confidence": 0.781, "size_score": 0.820,
      "shape_score": 0.705, "density_score": 0.313 }
  ],
  "rejected_pts":   [...],   // 点数超上限（max_cluster_pts），最先拒绝
  "rejected_size":  [...],   // 尺寸不符
  "rejected_shape": [...]    // 形状不符（长宽比/Z标准差）
}
```
`accepted` 按置信度降序排列，便于快速查看最佳目标。

### 可视化配色（Open3D）
```python
def confidence_color(conf):
    if conf < 0.45: return np.array([1.0, 0.15, 0.15])  # 红 LOW
    if conf < 0.70: return np.array([0.2, 0.45, 1.0])   # 蓝 MED
    return np.array([0.1, 0.9, 0.2])                     # 绿 HIGH
```
在 bbox 顶部放置球形标记：
```python
sphere = o3d.geometry.TriangleMesh.create_sphere(radius=0.4)
sphere.translate([b["cx"], b["cy"], b["cz"] + b["h"] / 2 + 0.4])
sphere.paint_uniform_color(color)
```

### GUI 设计要点
- **目录选择**：`ttk.Combobox` readonly 模式，预填已知目录，避免手动输入路径
- **文件多选**：`tk.Listbox(selectmode="extended")`，留空=分析全目录
- **参数预览**：单选文件时自动显示该 detail 文件的预标注参数（只读 Text 框）
- **滑块+输入框双向绑定**：`Scale` 拖动更新 `StringVar`，`Entry` 输入更新 `DoubleVar`
- **后台线程**：`threading.Thread(target=_worker, daemon=True)` 运行 analyze_file，`queue.Queue` 传回日志

## 踩过的坑

| 坑 | 原因 | 解决 |
|----|------|------|
| `boundary_tol` 对单侧约束（如 `z_std` 只有上限）需特殊处理 | `hi=+inf` 时 `span=hi-lo=inf`，除法出 NaN | 分类处理：`isinf(lo)` / `isinf(hi)` / 双侧有限 |
| 仅1~2个接受目标时 z-score 无意义 | `std≈0` 导致除零或全部被标为离群 | 判定前检查 `len(accepted) >= 3` 且 `std > 1e-9` |
| WASD 平移方向与直觉相反 | Open3D `translate(dx, dy)` 的 dx/dy 是屏幕像素偏移，正负含义与直觉相反 | 实测确认：W→`(0, +PAN_STEP)`，S→`(0, -PAN_STEP)`，A→`(+PAN_STEP, 0)`，D→`(-PAN_STEP, 0)` |

## 调参工作流

```
1. 跑一批窗口（5~10个）→ 生成 detail JSON
2. analyze_detail.py --gui：默认预设看一遍
   - 【1】看参数敏感度：区分度>30%的字段是关键
   - 【2】看疑似漏检：超出幅度集中在哪个字段？是否值得放宽？
   - 【3】LOW目标>3个 → 检查 density 弱说明 min_pts 过高，shape 弱说明阈值偏严
   - 【4】误报多 → 收紧 eps（DBSCAN）或提高 min_cluster_size（HDBSCAN）
3. 调整参数后重跑，对比前后分层比例变化
4. 参数稳定后全量运行
```
