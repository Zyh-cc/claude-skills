# 数据集项目目录结构重组：对齐规范结构并修正硬编码路径

## 版本日志
| 版本 | 日期 | 变更内容 |
|------|------|----------|
| v1.0 | 2026-04-11 | 初始版本，来自 AeroGround-Dataset 项目结构优化 |

## 问题场景

项目开发过程中脚本输出路径随手写死，导致实际 data/ 目录层级与 README/配置模板定义的标准结构不一致。需要在不破坏数据的前提下，批量迁移目录并同步修正所有脚本引用。

典型症状：
- `data/frame-pcd-ground/` 应在 `data/processed/` 下
- `data/splits/` 应在 `data/dataset/` 下
- 多个脚本硬编码了旧路径

## 解决方案

### 推荐方案（先移动目录，再修脚本，最后更新文档）

**Step 1：明确目标结构**

以 `paths_template.yaml` 或 `README.md` 的目录结构为权威标准，逐一列出「实际位置 → 目标位置」对照表。

**Step 2：批量移动目录（mv，不要 cp，保留 inode）**

```bash
mv data/frame-pcd-ground data/processed/frame-pcd-ground
mv data/frame-pcd-nonground data/processed/frame-pcd-nonground
mv data/ground_compare data/processed/method_comparison
mkdir -p data/dataset/splits && mv data/splits/split.json data/dataset/splits/
mkdir -p data/dataset/annotations && mv data/pre_annotations data/dataset/annotations/pre_annotations
```

**Step 3：创建缺失的占位目录**

```bash
mkdir -p data/dataset/train data/dataset/val data/dataset/test
touch data/dataset/train/.gitkeep data/dataset/val/.gitkeep data/dataset/test/.gitkeep
mkdir -p data/dataset/annotations/human_corrected data/dataset/annotations/golden_set
touch data/dataset/annotations/human_corrected/.gitkeep data/dataset/annotations/golden_set/.gitkeep
```

**Step 4：找出所有引用旧路径的脚本**

```bash
grep -rn "旧路径关键词" src/ --include="*.py"
```

逐一用 Edit 工具修正，不要用 sed 批量替换（防止误改注释或字符串拼接）。

**Step 5：同步更新 README 和配置模板**

- 目录树中的文件名、路径
- 新增脚本列表
- 文档名变更

## 踩过的坑

| 坑 | 原因 | 解决 |
|----|------|------|
| README 中的目录树用了全角 `│` 字符 | Edit 工具的 old_string 需完全匹配，复制时需保留全角符号 | 先 Read 目标行，再复制原文到 old_string |
| 部分脚本路径已经是正确的新路径 | 开发过程中有些脚本已经写对了 | grep 后逐条核对，不要盲目批量替换 |
| data/ 在 .gitignore 中，移动操作 git 不感知 | 数据目录不进版本库 | 只需提交脚本和文档变更，数据目录在服务器本地操作即可 |
