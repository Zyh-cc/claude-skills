## 执行流程

**Step 1：询问确认**
先问用户：「记录哪部分？科研/开发，还是生活，还是都要？」
如果用户已经在问题里说明了（如"记录今天的开发"），跳过此步。

**Step 2：确定文件路径**
```
路径：E:\ClaudeCode\ClaudeLogs\YYYY-MM-DD.md
规则：
  - 文件不存在 → 直接创建
  - 文件已存在（同一天有过记录）→ 追加，用 --- 分隔，不覆盖
  - 科研和生活内容同一天 → 分两个独立区块，各自 ---
```

**Step 3：按类型写内容**

### 科研 / 开发：精简风格

写**决策 + 原因 + 结果 + 下一步**，不写过程、命令、报错细节。

```
工作目录：`路径`

- **决策**：做了什么选择，为什么（一句话）
- **产出**：核心是什么
- 下一步 / 阻塞点
```

### 生活：朋友视角，有温度

像一个朋友替另一个朋友记录——有情绪，有具体细节，读起来像在聊天。

- 看电影/书 → 写被什么打动，或没被打动
- 心情/心事 → 写那个情绪是什么感觉，不只是结论
- 喜欢的人 → 写那个具体瞬间
- 新运动/技能 → 写第一次做对时的感受

**避免**：干燥事件清单（"今天看了电影，很好看"）

**Step 4：写入并确认**
写完后告知用户：「已追加到 YYYY-MM-DD.md」，不需要展示全文。

---

## 示例

**生活（喜欢的人）：**
> 今天在图书馆又碰到她了。她在靠窗的位置坐着，阳光正好打在她翻书的手上。没去打招呼，坐到了另一头，偷偷看了她两眼，然后假装很认真地看自己的书。回去的路上一直在想要不要下次鼓起勇气说句话。

**生活（新运动）：**
> 今天第一次打网球。前半小时完全找不到感觉，球拍挥空三次算正常。后来有个瞬间，球正好打在甜区，手感完全不一样——原来这就是"吃球"的感觉。就那一下，他喜欢上这项运动了。
