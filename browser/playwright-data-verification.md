## 触发条件

以下任一情况触发本流程：
- 文档中某数据"来源不明"或"无法核实"
- 内部数字与文档数字不一致，需先判断口径再决定用哪个
- 用户说"这个数字靠谱吗""帮我查一下"

---

## 工作流

### Step 0：搜索前确认（检查点）

告知用户准备搜索什么，避免搜错方向：

> "我准备用百度搜索「{关键词组合}」来核实这个数据，搜索方向对吗？"

**关键词构建规则（输入→关键词的转换方法）：**

| 数据类型 | 关键词结构 | 示例 |
|---------|-----------|------|
| 人数/规模 | 领域词 + 人群词 + 数字 + 动作词 | `彝绣 绣娘 5200 就业` |
| 金额/产值 | 地区 + 行业 + 产值/销售额 + 年份 | `南华 彝绣 产值 2024` |
| 政策/规划 | 发文机关 + 关键政策名 + 年份 | `楚雄州 彝绣产业 规划 2024` |
| 来源不明 | 原文关键短语（带引号） + 地区 | `"5200名绣娘" 南华` |

若数字来源已有线索（如"内部文件说是A县的数据"），在关键词中加入地区限定词。

---

### Step 1：执行搜索

```
1. browser_navigate → https://www.baidu.com
2. 在搜索框输入关键词，提交
3. browser_snapshot 读取结果页
```

---

### Step 2：读取 snapshot（重点看什么）

snapshot 很长，按优先级只看以下信息：

**优先看**（决定是否可信）：
- `link` 文本中是否出现：县/市/省**人民政府**、**人民日报**、**新华社**、省级**日报**、官方统计局
- 结果摘要中是否出现与文档**完全一致**的数字和表述

**次要看**（判断口径）：
- 发布时间：是否与文档引用的时间吻合？
- 地理范围：是"全县"还是"全州"还是"全省"？（口径不同则数字不能直接比较）
- 统计对象：如"绣娘"≠"高级绣娘"≠"注册绣娘"，需区分

**忽略**：
- 招聘网站、贴吧、自媒体、问答平台的结果

---

### Step 3：判断并给出结论（检查点）

向用户呈现核实结果，格式如下：

```
核实结果：
- 搜索词：{关键词}
- 找到来源：{来源名称} / 未找到权威来源
- 发布时间：{时间}
- 原文表述：「{摘要原文}」
- 与文档的关系：{口径一致 / 口径不同（说明差异） / 无法确认}
- 建议处置：{保留 / 替换为XX / 加限定词 / 模糊化 / 标注待核实}
```

等用户确认后再动手修改文档。

---

## 判断框架

| 情况 | 结论 | 建议处置 |
|------|------|---------|
| 官方来源，口径一致 | 数据可靠 | 保留；"余"字以官方原文为准 |
| 官方来源，口径更大（如全州 vs 全县） | 文档是子集，需区分 | 加限定词说明范围 |
| 内部数字 ≠ 公开数字 | 口径可能不同 | 先问清楚各自统计口径 |
| 找不到来源 | 数据存疑 | 模糊化或标注"待核实" |
| 搜索无结果 / 百度访问失败 | 无法通过搜索核实 | 直接询问用户数据来源 |

## 踩过的坑

| 坑 | 原因 | 解决 |
|----|------|------|
| Windows 上 Playwright MCP 启动失败 | `command` 直接写 `npx`，Windows 需 `cmd /c` 包装 | `~/.claude.json` 改为 `"command": "cmd", "args": ["/c", "npx", "@playwright/mcp@latest"]` |
| snapshot 太长读不完 | 百度结果页结构复杂 | 只看 `heading` + `link` + 摘要文本，忽略导航/热搜/广告区域 |
| 搜到的数字比文档大 | 口径不同（如全州 vs 全县） | 不要直接替换，先判断口径关系 |

## 典型案例

**场景**：方案文档写"全县5200余名绣娘实现稳定就业"，内部文件数字为3882人

**处理过程**：
1. 搜索词：`彝绣 绣娘 5200 就业`
2. 找到来源：南华县人民政府官网、云南日报（2025年）
3. 原文："全县5200名绣娘通过指尖经济实现稳定就业"
4. 结论：5200 = 全县稳定就业总数，3882 = 其中高级绣娘，两者口径不同不矛盾
5. 处置：保留5200，去掉"余"字（官方原文无"余"）
