# 功能退化排查："之前好用，现在坏了" → 先查 git log，再谈根因

## 版本日志
| 版本 | 日期 | 变更内容 |
|------|------|----------|
| v1.0 | 2026-04-13 | 初始版本，源于 Open3D 鼠标回调破坏旋转/平移的排查复盘 |

## 问题场景

用户说「之前可以，现在不行了」——表明某个**已知可工作的状态**发生了退化。

常见描述：
- "之前可以旋转，现在不行了"
- "昨天还能跑，今天报错了"
- "改了这个功能之后，那个功能坏了"

## 诊断路径（按顺序执行）

### 第一步：查 git log，找变化点（必须最先做）

```bash
git log --oneline <涉事文件>
```

找到最近改动这个文件的 commit，立刻就知道「是什么改动引入了问题」。

**不要跳过这一步去做任何假设或理论推演。**

### 第二步：用 git show 看具体改动

```bash
git show <commit_hash> -- <文件>
```

对照改动内容和症状，通常根因直接可见。

### 第三步：如果是依赖/环境问题（无 git 变化）

才开始考虑：
- 库版本升级（`pip show <package>`）
- 系统环境变化
- 配置文件变动

## 反面教材

**错误流程**（本次实际发生）：
1. 查 Open3D 版本 ← 合理但非第一步
2. 翻 API 文档 ← 浪费时间
3. 找 pyi/源码文件 ← 无必要
4. 脑内推演 C++ 回调语义 ← 完全没有证据的假设
5. **最后才查 git log** → 第一条就是答案

整个过程多花了 10 倍时间。

**正确流程**：
1. `git log --oneline vis_preannot_window.py` → 第一条 `507eaef feat: register mouse callbacks`
2. `git show 507eaef` → 看到加了 `register_mouse_move_callback`
3. 得出结论：Open3D 0.19 中注册该回调拦截了鼠标移动事件
4. 用 ctypes 替代，修复完毕

## 核心规则

> **"之前好用，现在坏了"** → 第一步永远是 `git log <文件>`，先找到变化点，再谈为什么。

分析根因要有证据，不要在没有证据的情况下从理论假设出发。
